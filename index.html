    About this prototypeA product concept for Hyper's task log, by Satya

    The concept

    Hyper's agent does real work for a team: it sends emails, writes documents and follows up with people. Today that work disappears into chat history, so nobody can see what was done, what is still open, or what it was based on.

    The task log gives every piece of work a home. Each task shows what was done, what needs you, everything that happened, what it produced and the sources it drew on, and you can act on it right there.

    What's simulated and what's real

    Simulated

    • The agent. Its replies are built from the sample data, not from an AI model.
    • Sending. No email or message ever leaves the page.
    • The people, replies, tools and sources. Priya, Notion, Gmail and the rest are sample data.

    Designed to be real

    • The task list and how each status (Needs you, Waiting, Done) is worked out from what's still open.
    • The task page: what was done, needs attention, activity, artifacts and sources.
    • Draft, review, send, and watching the task update. Marking an item handled.
    • The task chat beside each task, and tracing any task back to the chat it came from.

    What it would take to make it real

    • The agent. An AI model such as Claude, called through Anthropic's API from a small server, connected to the team's tools (Gmail, Notion, Slack, Sheets) so it can read and act on them.
    • What the log stores. One record per task: its name and summary, the open items (who, where, when), every activity, the artifacts themselves, links to the sources, and the chat it came from. A standard database is enough.
    • Where it could go wrong. The agent could misread a reply and set the wrong status, so people can always mark items handled or correct them. Sending on someone's behalf needs their approval every time. Sources get edited or deleted, which is why the log keeps showing them. And the log must only show each person what they can already see in the original tools.
